# Working in this repository

## Git identity policy

**All commits in this repository MUST be authored as the repository owner.** When Claude (or any AI assistant) creates commits here, it must:

1. **Use the repository owner's git identity** — not "Claude", not "Anthropic", not any AI-related identity.
   - The local `git config user.name` / `user.email` is set to the owner. Do not change it.
   - Do not pass `--author` to `git commit` to override the configured identity.

2. **Never add Claude/AI attribution to commit messages.** This includes (non-exhaustive):
   - `Co-Authored-By: Claude <noreply@anthropic.com>` (or any variant)
   - `🤖 Generated with Claude Code` (or any variant)
   - `https://claude.ai/code/session_…` links
   - Any reference to "Anthropic", "Claude Code", "AI assistant" in commit subjects or bodies
   - "Generated by", "Created with AI", etc.

3. **Never add AI attribution to pull request descriptions, issue comments, or any other GitHub artifact** posted on behalf of the owner.

4. **A `commit-msg` hook enforces rule 2 locally.** It rejects any commit whose message contains the banned patterns. If it fires, fix the message — do not use `--no-verify` to bypass it.

5. **Install the hooks once per clone** by running:
   ```bash
   git config core.hooksPath .githooks
   ```
   This is also part of the repo's standard setup; if you cloned fresh, run it before your first commit. The hooks are stored at `.githooks/` and tracked in version control.

## Standard commit format

- Subject line: lowercase, imperative mood, ≤72 chars (e.g., `docs: add SECURITY.md`).
- Body: explain *why*, not *what*. Wrap at 72 chars.
- No emojis unless the rest of the repo already uses them in commits.
- No footer attribution lines.

## When in doubt

If you're unsure whether something belongs in a commit message, leave it out. The git log is for humans reading the project, not for tracking which tool wrote which line.
